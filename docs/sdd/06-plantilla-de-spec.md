# Plantilla de spec

Usa esta plantilla para empezar una spec pequeña y bien trazable.

```md
# Nombre de la funcionalidad

## Objetivo

## Problema que resuelve

## Usuarios o actores

## Alcance

## Fuera de alcance

## Requisitos funcionales

## Requisitos no funcionales

## Flujos principales

## Casos alternativos

## Casos límite

## Criterios de aceptación

## Dependencias

## Riesgos

## Preguntas abiertas
```

## Checklist de calidad

- ¿Se entiende qué se quiere hacer?
- ¿Se entiende por qué importa?
- ¿Los criterios son comprobables?
- ¿Hay casos límite?
- ¿Queda claro qué no entra?
- ¿Hay preguntas abiertas explícitas?

## Ejemplo de buen criterio

- Malo: “El usuario debe tener una buena experiencia”.
- Bueno: “Cuando el usuario guarda el formulario con campos válidos, el sistema confirma el guardado en menos de 2 segundos y muestra el elemento en la lista sin recargar la página”.
