# Flujo recomendado

Tu intuición era buena, pero el flujo completo suele verse así:

1. Constitución o principios del proyecto.
2. Spec.
3. Clarificación.
4. Plan.
5. Tareas.
6. Implementación.
7. Validación y review.

## Qué hace cada paso

### 1. Constitución

Define reglas estables: calidad, testing, UX, performance, seguridad, etc.

### 2. Spec

Describe el comportamiento deseado:

- objetivos
- usuarios
- casos de uso
- restricciones
- criterios de aceptación
- edge cases

### 3. Clarificación

Resuelve huecos y ambigüedades antes de planificar.

### 4. Plan

Traduce la spec a decisiones técnicas:

- arquitectura
- módulos
- modelo de datos
- integración
- estrategia de pruebas

### 5. Tareas

Convierte el plan en pasos pequeños, ordenados y verificables.

### 6. Implementación

Se codifica siguiendo el orden de las tareas.

### 7. Validación y review

Se comprueba si lo entregado cumple la spec y se corrigen desviaciones.

## Regla práctica

Si no puedes verificar una afirmación en la spec, probablemente está demasiado implícita.
